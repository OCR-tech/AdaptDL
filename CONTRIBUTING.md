## Code of Conduct
Please note that this project has a [Code of Conduct](#conduct) that we expect all contributors to follow. By participating in this project, you agree to respect the guidelines set out in the Code of Conduct.

## How to Contribute
There are several ways to contribute to **AdaptDL** project:

## Reporting Issues
If you find a bug or an issue with the project, please follow these steps:

1)  **Search Existing Issues**: Before creating a new issue, please check if it has already been reported. This helps avoid duplicates and saves time.

2)  **Create a New Issue**: If the issue hasn't been reported, feel free to open a new issue by providing a detailed description of the problem. Please include:
    - A clear and descriptive title.
    - Steps to reproduce the issue (if applicable).
    - Expected behavior and actual behavior.
    - Any relevant screenshots, logs, or error messages.

## Proposing Enhancements
If you have an idea for a new feature or enhancement, please:

1)  **Check Existing Requests**: Make sure the feature request hasn't already been proposed.

2)  **Create a New Issue**: Provide a detailed description of the feature, its use case, and why it would improve the project. The more details you provide, the easier it will be for us to understand your suggestion.

## Submitting Code
We welcome code contributions! To submit code, follow these steps:

1)  **Fork the Repository**: Click the "Fork" button at the top right of the repository to create your own copy.

2)  **Create a New Branch**: Create a new branch for your changes. It's a good practice to use descriptive names for your branch.

    ```
    git checkout -b my-feature-branch
    ```
3)  **Make Changes Locally**: Make your changes in your local repository. Be sure to follow the style guide and keep your changes focused on a single issue or enhancement.

4)  **Commit Your Changes**: Once your changes are ready, commit them with clear and concise commit messages. Please follow the commit message convention for consistency.

    ```
    git commit -m "Add feature X to improve functionality"
    ```
5)  **Push Your Changes**: Push your changes to your forked repository.

    ```
    git push origin my-feature-branch
    ```
6)  **Open a Pull Request (PR)**: Go to the original repository and open a pull request. Provide a detailed description of your changes in the PR. Be sure to reference the issue it resolves (if applicable) by using `#issue_number`.

    Example:
    ```
    Fixes #123 - Add feature X to improve functionality
    ```

7)  **Participate in the Review Process**: After submitting your PR, maintainers will review your changes. Be prepared to make revisions based on feedback.


## Development Process
We follow a structured process for managing contributions:

1)  **Issues and Pull Requests**: All contributions must be submitted via pull requests (PRs). Issues should be opened for discussion before creating a PR for new features or bug fixes.

2)  **Branch Naming**: Use descriptive branch names related to the feature or fix you're working on, e.g., `fix/issue-123` or `feature/add-login`.

3)  **PR Reviews**: All pull requests must be reviewed by at least one maintainer. They may suggest changes or improvements, and you will need to address these before the PR is merged.

4)  **Merging PRs**: Only maintainers have the permissions to merge pull requests. Once a PR has been approved and any necessary tests pass, it will be merged into the main branch.
